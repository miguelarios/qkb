> Supersedes `2026-07-20-typescript-rewrite.md` (complete: shipped as npm `@miguelarios/qkb`
> v0.4.x) as the source of truth. Execute tasks in order; each task is one PR with tests.
> Steps use checkbox (`- [ ]`) syntax for tracking — tick them as they land.

## 0. What qkb is (and why it isn't just QMD)

qkb is a search engine for **knowledge-base** markdown: an Obsidian-style vault whose notes carry
YAML frontmatter properties. It is served to humans (CLI) and agents (MCP).

[QMD](https://github.com/tobi/qmd) is the reference for architecture and local models (hybrid BM25
+ vector + RRF, `embeddinggemma` GGUF via node-llama-cpp, collections, HTTP MCP). The difference is
frontmatter. QMD indexes frontmatter as ordinary content; its metadata filters only read a
QMD-namespaced block (`qmd: metadata: {...}`). qkb treats a vault's **existing** properties as
structured data: an opt-in contract, a stable `id`, dates, `context` grouping with descriptions,
`source` siblings, weighted title/tags/context columns, and alias mapping for vault conventions.

## 1. Definition of done (MVP)

- [x] Reads a directory of markdown files and separates frontmatter from body.
- [x] Opt-in contract (kept deliberately): a note is indexed only if it has `context` and/or
  `source`; an opted-in note also needs a unique `id` and a parseable date.
- [x] A fixed core set of properties (`id, type, title, context, source, date, created, tags`) with
  configurable aliases.
- [ ] **Declared extra properties** (Task 5): users list extra frontmatter keys in config, each with
  a short description; declared keys are searchable, embedded, returned in results, and described to
  agents.
- [x] Local-first embeddings on macOS (Metal) using QMD's default model (`embeddinggemma-300M` GGUF).
- [x] Optional remote Ollama (`provider = "ollama"`, `ollama_host = "http://<gpu-host>:11434"`).
- [ ] **MCP over stdio and Streamable HTTP** (Task 2), so qkb can run beside an agent or as a
  network service in a container.
- [ ] **Safe as a long-running service** (Task 3): concurrent read/write on SQLite, and automatic
  re-indexing when the vault changes (e.g. Obsidian Sync or an agent writing notes).
- [ ] **Multiple vaults** (Task 4), QMD-collection style, filterable per search.
- [ ] TypeScript only — no Python in the repo (Task 1).
- [ ] Acceptance (Task 6): ≥8/10 golden queries in the top 3 via CLI, stdio MCP, and HTTP MCP.

**Target deployments:**

1. *Local:* on a Mac, `llama` provider, stdio MCP or HTTP on `127.0.0.1` (one long-lived process,
   one model load, many clients). Includes the "agent maintains its own markdown wiki" case — the
   agent's pages just need `id` + `context`/`source` frontmatter.
2. *Server:* a container that shares a volume with a vault sync process, uses a remote Ollama for
   embeddings, and serves HTTP MCP to clients on the local network.

**Out of scope for the MVP:** LLM re-ranking and query expansion (QMD's other two local models;
`--rerank` stays a stub), writing to the vault (qkb stays read-only — writers are other tools; qkb
only re-indexes what they change), attachment extraction.

## 2. Tasks

- [ ] **Task 1 — TypeScript-only cleanup.**
  Remove `legacy/python/` and the Python workflows (`ci-legacy-python.yml`, `release-python.yml`);
  the Python implementation stays on PyPI (`qkb-search` v0.3.0) and in history — tag `v0.4.3` is
  the last tree carrying `legacy/python/`, which the "ported from" comments cite. Move the
  golden-queries example YAML to `scripts/`. Drop the Python-only ignore/tooling entries
  (`.gitignore`, `biome.json`, `tsconfig.json`, `vitest.config.ts`). Fix `test/workflows.test.ts`
  (its hard-coded file list broke when `claude-code-review.yml` landed, turning `main` red) and add
  a guard that no Python workflow comes back. Update `CLAUDE.md`, the README's legacy section, and
  stale comments (`src/types.ts`). Bump `Formula/qkb.rb` to the published 0.4.3 tarball. Mark the
  TypeScript-rewrite plan complete. **Test:** `npm test`, `biome check`, `tsc --noEmit`, build.

- [ ] **Task 2 — Streamable HTTP MCP transport.**
  `qkb mcp` stays stdio. `qkb mcp --http [--host 127.0.0.1] [--port 8181]` serves the same three
  tools over the SDK's `StreamableHTTPServerTransport` at `POST /mcp` (stateless, JSON responses),
  plus `GET /health`. The provider and DB connection are built once per process and shared across
  requests (reuse `withLock` in `src/server/mcp.ts`). Default bind is loopback. Reject a
  browser `Origin` that isn't loopback unless `QKB_ALLOWED_ORIGINS` allows it, as QMD does (DNS
  rebinding guard). Config: `[mcp] host/port` + `QKB_MCP_HOST`/`QKB_MCP_PORT`. **Tests:** in-process
  server on an ephemeral port — `initialize`, `tools/list`, a `qkb` search against a fake-provider
  index, origin rejection, `/health`. README: client config for both transports.

- [ ] **Task 3 — Service readiness: concurrency + auto re-index.**
  Open SQLite in WAL mode with a `busy_timeout`, so an ingest/embed can run while the server serves
  reads without `database is locked`. Add `qkb mcp --http --watch [--interval <sec>]` (and a
  standalone `qkb watch`): re-run incremental `ingest` + `embed` on a timer (default 300s), with a
  filesystem-event trigger as an optional fast path. Runs are serialized, one at a time, and a
  failed run is logged without killing the server. The content-hash fast path already makes a
  no-change pass cheap (<5 s). **Tests:** a writer and a reader on one DB file don't lock each other
  out; the watch loop picks up an added, edited, and deleted note (fake provider, temp vault,
  injected clock).

- [ ] **Task 4 — Multiple vaults.**
  Config gains `[[vaults]]` entries (`name`, `path`), keeping the single `[vault]` form as sugar for
  one entry. One database; `documents` gains a `vault` column. **Decide in this task:** whether the
  primary key becomes `(vault, id)` — the same note mirrored in two vaults would otherwise collide —
  and write the answer as an ADR. Ingest walks each vault; the deletion sweep is scoped per vault.
  Obsidian URIs use the note's own vault name. Search gains `--vault <name>` (repeatable) in the CLI
  and a `vaults: string[]` argument on the MCP `qkb` tool. `qkb status` / `qkb_status` report
  counts per vault. Schema version bump + clear "re-ingest required" message on an old DB.
  **Tests:** two temp vaults — isolation, per-vault filter, per-vault sweep, URI vault name.

- [ ] **Task 5 — Declared extra properties.**
  ```toml
  [frontmatter.fields]
  project   = "Project this note belongs to"
  attendees = "People present in a meeting"
  ```
  Declared keys (after alias resolution) are: (a) indexed in a new FTS5 `fields` column with its own
  `fts_weights` entry; (b) prepended to each chunk's embedded text as `key: value` lines, so vectors
  carry them; (c) returned as a `fields` object in CLI `--json`, `qkb get`, and MCP results; (d)
  described to agents — the `qkb_status` tool and the `qkb` tool description list each declared
  field and its description. Undeclared keys keep today's behavior (stored in `metadata`), and are
  now also returned by `qkb get` without affecting ranking. Changing the declared set changes vectors
  → `qkb status` warns and `qkb embed --full` is required (reuse the model/dim guard). Add a filter:
  `--field key=value` (CLI) / `fields: {key: value}` (MCP). **Tests:** parser, FTS column, embedding
  text, output shapes, guard on declared-set change.

- [ ] **Task 6 — Container + acceptance.**
  A `Dockerfile` (Node 22 slim, `npm i -g @miguelarios/qkb`, vault mounted read-only at `/vault`,
  DB + model cache on a volume, `qkb mcp --http --host 0.0.0.0 --watch`) and a compose example
  wired to a remote Ollama. README deployment section. **Acceptance (owner-run, real vault):**
  golden queries ≥8/10 via CLI, stdio MCP, and HTTP MCP; a vault edit shows up in search within one
  watch interval; ingest + serve concurrently with no lock errors. Record results in this plan.

## 3. Constraints (unchanged)

Public repo — synthetic test data only; the vault is never written; unit tests run offline with the
`fake` provider; no release tags from agents. See `CLAUDE.md`.
